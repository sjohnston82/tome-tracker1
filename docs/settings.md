# Settings behavior and verification

Appearance controls apply to the whole app, not just Settings. Tailwind's dark variant follows the root `.dark` class; background variables use the same selector. A head bootstrap applies the validated saved preference before paint, and the global ThemeProvider keeps it active on navigation. System mode listens for OS changes; explicit Light/Dark choices take precedence. Cross-tab preference changes are observed. Storage failures do not prevent changing the current theme and are reported in Settings. Appearance is a preference of this browser, not a database setting.

Sync now downloads the signed-in user's library into IndexedDB and refreshes book/author counts and the last-synced time. Failed or offline syncs do not report success. Clear library cache removes this app's local book data, cached cover images and the obsolete library-sync response cache. It does not remove the app shell, theme preference, server-side books or reading history. Failed cache writes roll back atomically, and syncs started before a clear cannot refill the cache afterward. Concurrent Settings actions are disabled while an operation runs.

Offline records are tagged with their verified owner. Reads, searches, ownership checks and cache counts do not expose another account's records or untagged legacy caches. A legacy cache becomes available after the next successful authenticated sync. Library sync responses include the account ID, use private/no-store headers and are no longer cached as generic service-worker API responses. The client checks the response identity before displaying or caching it.

Sign out checks the server response, clears local library data and refreshes navigation. A failed server sign-out leaves the page in place with an error. If the server action succeeds but local cleanup fails, the login page explains the cleanup issue. Account deletion remains behind an explicit, keyboard-accessible confirmation. Cancel performs no deletion; failures stay visible inside the dialog. Successful deletion clears the local cache and session navigation. Offline users can clear local data, but network account operations are disabled with an explanation.

Theme/provider, Settings interaction and real IndexedDB behavior are covered by automated tests using browser mocks and an isolated fake IndexedDB. HTTP tests use only disposable synthetic accounts to verify private sync, logout cookies, unauthorized deletion, and cascaded deletion of that test account's books and reading logs. Do not exercise deletion against a personal or production account during routine verification.

## Library, reading and accessibility preferences

Preferences are stored per account in this browser and validated before use. Library authors remain grouped alphabetically by surname; book order can be series/title/publication year (unknown years last). Users can choose initial author expansion and series details. Currently Reading can be hidden. The default progress input can be pages or percentage; percentage requires a saved total and is rounded to an integer page. Existing logs and baselines remain unchanged. Text size and reduced motion apply globally, respect OS motion preferences, and browser zoom is enabled.

Automatic cover lookup can be disabled for manual additions, scans, metadata-search additions and the library background pass. Explicit cover choices and edition-provided covers remain available. The manual missing-cover retry is still available. Offline-cover downloads fetch approved provider image endpoints through an authenticated, size-limited proxy without following redirects. Both thumbnail and full-size variants are cached. Book covers use these local images, including during development when the production service worker is disabled. Downloads report partial failures and unsupported URLs and stop if the local cache is cleared. These are public images, not book ownership data. Clearing library cache removes these images too.

## Backups and account changes

`GET /api/account/backup` exports a consistent account-scoped JSON snapshot. `?format=csv` exports owned books for spreadsheets, quoting fields and neutralizing formula injection. JSON includes authors, physical books, works (including unowned works), series entries, omnibus relationships, reading sessions/logs and collection-import manifests/reports. Manual metadata, cover locks, timestamps and import keys survive restore. Account records, passwords, sessions and reset tokens are excluded. Browser preferences/theme and image binaries are not included. Keep backup files private: reading notes and import source data are included.

Restore validates the version, bounded size, unique keys and relationships before writing. The UI previews counts and requires confirmation. Restore is transactional, remaps IDs and requires an empty library; it never merges or replaces an existing collection. Repeated nonempty restores fail without writing. The server enforces the empty-library condition inside a serializable transaction. API confirmation uses `X-Confirm-Restore: yes`; preview uses `?preview=1`. Backup files are limited to 20 MB. Empty exports can be restored safely but naturally contain no records.

Email/password changes require the current password, enforce the existing password rules and a 72 UTF-8-byte limit, rate-limit attempts, check concurrent credential changes, invalidate reset links, and renew the current session. New sessions carry a credential fingerprint checked against the database. Changing email or password invalidates older fingerprinted sessions; legacy sessions also check account update time and email. Login remains reachable to renew revoked sessions. Email changes take effect immediately; email verification is not part of the existing authentication system.

About & diagnostics displays app version, connectivity and sync state. Copied diagnostics contain only version/support flags and cache counts/time, excluding account identity, titles, notes, credentials and server URLs. Clipboard failures expose selectable text.

Verification adds preference persistence/isolation/storage failures, Settings form/restore-confirmation failures, book ordering, percentage conversion, backup schema/CSV safety and offline-cover URL filtering. Disposable database tests round-trip corrected metadata, overlapping series, omnibus contents, missing works and reading notes; repeated restores leave both accounts untouched. HTTP tests verify authorization, exports, restore guards and successful/failed credential changes with session revocation. No personal account or production database is used by those tests.

Imports, backup restores and reading-log writes retry the complete transaction up to three times after PostgreSQL serialization conflicts (P2034). Validation, uniqueness and empty-library errors are not retried. Exhausted conflicts surface as failures; no partial transaction is committed.

## Library shelf view

Author list / Book shelves switches between the existing author dropdowns and one horizontal carousel per surname letter. Settings > Library defaults > Library view controls the same browser preference. Both layouts retain letter sections, alphabet jumps, author filtering, the configured book order within each author and optional series details. Authors stay sorted by surname within each letter.

Each letter has a left-aligned cover row with no initial selection, dimming or center snapping. Fine-pointer hover enlarges a cover by 12%; the first and last covers grow inward so they are not clipped. Vertical padding leaves room for the enlarged image. The shared caption shows the hovered book’s title, author and optional series details, returning to the book count when interaction ends. Keyboard focus exposes the same metadata with the normal accessibility outline, without applying hover zoom or selecting an initial book. Scrolling alone does not select a book.

The native scrollbar is hidden in Firefox and WebKit/Chromium. Moving a mouse within 64 pixels (at most a quarter of the row width) of either edge starts continuous scrolling, accelerating toward the edge. The animation stops in the middle, on pointer exit/down, a wheel gesture, reaching a boundary, page blur/visibility changes or unmount. Touch and pen input do not start mouse-edge scrolling; native swiping remains available. Focusing a row enables Left/Right and Home/End scrolling. Reduced-motion preferences remove smooth keyboard scrolling and CSS transition animation. Cover links still open book details.

Covers retain lazy medium-sized images, original-image fallback, offline cache, loading skeleton and missing-cover placeholders. Tests cover one row for multiple authors under the same letter, no preselection, hover metadata/clearing, both edge directions and cleanup, touch/drag exclusion, keyboard navigation, saved views/filtering and the unchanged author-list layout. No migration or library-data changes are required.
