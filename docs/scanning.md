# Phone scanning

The camera scanner requests the rear-facing camera with ideal 1280×720 video, without audio. It decodes EAN-13 and common retail/linear formats, accepts genuine ISBN-10 or ISBN-13 identifiers, and verifies the normalized 978/979 prefix and checksum locally. Invalid/non-book codes leave scanning active and show guidance rather than initiating a provider lookup. The small adjacent price barcode is not an ISBN.

Each active attempt accepts one result synchronously. Parent callback changes do not restart capture; selecting Scan again starts a new attempt and permits the same ISBN immediately. Capture tracks stop after acceptance, when paused, on navigation and when a pending permission request completes after cleanup. Camera startup and permission/device failures have separate feedback, and camera failures have a retry control. The video element remains mounted during camera errors and is replaced between attempts to isolate late asynchronous work. Paused capture is compact so lookup results remain near the page heading.

Automated component tests mock the camera and decoder to verify callback replacement, repeated frames, immediate rescanning, old callbacks, non-book/invalid barcodes, late permission completion, permission retry and inactive/unsupported states. These tests do not prove physical-camera barcode recognition or autofocus on a particular handset. Phone testing should cover a recognized ISBN, an unknown ISBN, repeat scanning, existing-ISBN ownership, permission denial/retry and leaving/reopening Scan.

For remote testing the phone needs HTTPS, or localhost via USB port forwarding. A temporary HTTPS tunnel can reach the local development application. Imported books without an ISBN cannot be identified as owned solely from a barcode; ownership matching still depends on a recorded ISBN. Provider lookup and Add to library are separate steps, and scanning alone does not add a record.

## Retail barcodes and incorrect catalog assignments

ISBN extraction requires complete identifiers: a ten-digit substring inside a longer UPC/EAN must never become an ISBN, even if its checksum coincidentally passes. The lookup endpoint uses the same strict parser and no permissive fallback. Both metadata providers verify the edition’s own identifiers (including ISBN-10/13 equivalence); Google searches skip unverified/unrelated hits rather than accepting the first result.

The scan page accepts printed ISBN-10/13 with hyphens, shows the normalized ISBN submitted, prevents concurrent camera/manual lookups, and offers title/author search. Search selections never copy another edition’s ISBN or publication year. Keeping the printed ISBN despite catalog disagreement requires an explicit checkbox. Corrected selections lock their chosen/missing cover and disable automatic cover lookup for that addition. Background metadata enrichment skips conflicting titles, protecting corrections from a miscatalogued ISBN. Saving still requires Add to library; existing records are not overwritten.

Live read-only checks of the user’s copies confirmed 0553579908 → 9780553579901 (A Clash of Kings), 0451187849 → 9780451187840 (We the Living). For printed 0670030031 → 9780670030033, Open Library returned Synaptic self and Google returned Lake Wobegon Summer 1956 without an ISBN plus a Synaptic Self volume claiming the ISBN. ISBN verification alone cannot resolve incorrect source assignments; title search and explicit correction remain necessary for this copy. No catalog entries or user library records were modified by verification.

Validation for the scan recovery changes: 250 unit/component tests passed, including 19 new cases beyond the initial scanner lifecycle work; TypeScript passed. Live calls through the application’s metadata providers returned Martin/Rand correctly and found Keillor through title search. Physical handset recognition remains a user-device verification step.
