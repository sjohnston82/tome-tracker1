# Forward reading progress

The edition selector includes an optional ISBN search (hyphens and spaces accepted) and **Load more editions**. A custom search is read-only and never replaces the book's saved ISBN. Clearing the search ISBN browses by title/author. Explicit browsing returns larger batches, appends distinct options, and can examine up to 300 editions per matched Open Library work. Providers may not yet list recent tie-in editions; the manually editable Total pages field remains available. Pressing Enter in the ISBN field searches rather than submitting page settings.

To replace an edition length, open **Page settings → Choose another edition**, select a suggestion, then **Save page settings**. **Keep current edition** restores the saved value without writing. Before a session is started, **Find other editions** broadens the suggestions. These explicit searches use `?editions=all` on the page-count endpoint to include other editions even when an ISBN match exists. Automatic lookup still preserves saved lengths.

Library highlights physical editions marked Currently Reading above the alphabet list. Each card provides a page baseline, optional edition page count, a timestamped log with notes, and explicit completion. The same tracker is on book details; an Unread book can be started there. The page bar is hidden when the edition's total pages are unknown. Progress history can be corrected or removed; page settings can also be corrected. Removing completion explicitly reopens the book.

The additive migration creates reading sessions and their logs without updating books or backfilling history. An existing Read book stays undated until its owner deliberately initiates a future read by changing its status to Unread. An existing Currently Reading book starts with an unknown reading-start date and a user-entered baseline. Pages before that baseline are not credited. A new Unread read starting at page zero records a start date. Completion is dated only by the explicit Finish book / Save completion action; changing the ordinary reading-status dropdown does not manufacture a completion event.

Timestamps are stored as instants and displayed in the browser's local timezone. Entry times can be edited within the tracked reading period. Settings use the page count of the physical edition, not a work-level publication length. Corrections and revisiting a page do not double-count pages: progress uses the highest observed page minus the baseline, while the current page uses the latest chronological entry. Any future monthly statistics must allocate high-water increments chronologically and exclude the baseline. Books-per-year statistics must use explicit completed sessions, never import timestamps or status alone.

When no edition length is saved, the authenticated read-only `/api/books/:id/page-count` endpoint retrieves page-count suggestions. Verified ISBN identifiers take priority; a consistent exact-ISBN count can prefill an untouched new-session form, but nothing is persisted before explicit Start reading. Other editions, or conflicting ISBN counts, require selection or manual entry. Existing saved lengths and in-progress edits are never automatically replaced. For an existing session with unknown length, suggestions are available under Page settings and require explicit selection and Save page settings. Work-level median lengths, invalid values and unverified Google ISBN results are excluded. Google Books availability depends on provider quota; Open Library results remain available independently.

The authenticated `/api/books/:id/reading` endpoint GET retrieves the latest session. POST supports start, log, edit, delete and settings. Writes are serializable, version checked, scoped to the owned book and protected by a partial unique index allowing only one active session per edition. Repeated log request IDs return the original result without inserting duplicates. Completion, book status and log changes commit atomically. Previous reading sessions remain stored when another read is started. The first interface shows the latest session and its latest 30 history entries; all its logs are retained server-side. A session is limited to 10,000 entries. Logs currently require a network connection; the existing cached library remains usable offline.

This delivery implements currently-reading cards, page/time/note history, baseline and edition-length corrections, and explicit start/completion dates. Monthly/yearly dashboards, quarterly recaps and unread-owned recommendations are subsequent features using these records; they are not yet implemented. No legacy completion dates or historic page totals are inferred.

Local validation applies the migration only to the localhost Docker test database. On Windows, stop the dev server before `npx prisma generate`, then restart it so its Prisma client recognizes the new models. No production migration is authorized by these changes.
