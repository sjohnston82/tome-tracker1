# Series cleanup

Series → Merge duplicate series loads the actual saved series, including aliases already combined for display. Choose two series and a canonical name, then preview. The preview shows each source's title, author, publication year, series position, entry type, order confirmation and saved physical-copy link count.

Every duplicate work record or conflicting order requires an explicit choice: use a selected work's metadata and order for a combined entry, or keep distinct work records separate. Duplicate memberships of the same work ID require one order choice. Different descriptions require a retained or edited description. A final checkbox and Confirm series merge apply only the reviewed preview.

The server uses account-scoped repeatable-read previews, a snapshot hash, and a serializable transaction with conflict retries. A stale preview, unknown resolution, foreign record, name collision or missing conflict choice fails without partial changes. Successful merges consolidate memberships into the retained series and remove the duplicate series record. Physical books, original works, ownership relationships and reading logs are not rewritten or deleted. Combined work records remain available through ownership review; their saved links retain actual work provenance. Keep-separate choices prevent the display reconciler from collapsing intentionally distinct entries.

Versioned series management data uses the `tome:series-management` namespace. It preserves old series-name redirects and per-series work groups. Original collection imports follow redirects and map checklist memberships to the retained work without recreating duplicate series or discarded positions. Rejected ownership matches remain respected. Metadata review follows redirects when comparing source ordering with the retained checklist. Backup validation checks this data and restore remaps series/work IDs. No migration is required.

Validation includes explicit conflict and keep-separate UI controls, account boundaries, stale previews, malformed choices, preservation of physical records and manual metadata, competing merges, backup remapping and reimport behavior. Database/HTTP tests use isolated databases and generated accounts, never personal or production data. A merge cannot be undone in place; export a backup before a cleanup if you want the original series arrangement available for a full restore into an empty library.
